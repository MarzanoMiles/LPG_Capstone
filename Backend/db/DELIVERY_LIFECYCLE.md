Run `npm run migrate:delivery-lifecycle` from Backend before deploying this change. The migration is rerunnable, adds attempt/retry/restock/settlement fields and the unique DeliveryAction journal, and normalizes legacy Pending/Failed statuses and DR reference numbers. Fresh schema.sql and seed.js include the new schema.

GET /deliveries scopes rows to the authenticated company. Driver/Drivers tokens receive only their own active assignments; client driver IDs are ignored. Drivers may POST complete and fail only. Other authenticated management APIs reject driver tokens. Management edits accept only deliveredByUserId and remarks; legacy order delivery/status edits are blocked.

POST /deliveries/:id/{dispatch,complete,fail,settle,cancel} requires a requestId (8–64 word/hyphen characters). Reuse the same key and payload for network retries. The delivery row lock and unique (DeliveryID,RequestID) journal serialize operations. Journal entries retain user, timestamp, failure notes, return items, warehouse/reference and settlement authorization. UserActivity writes occur in the same transaction. Duplicate actions with a different key are rejected by state guards.

Only a failed attempt increments AttemptCount. Retries retain the driver and schedule the next business day at opening time in UTC+8. Final unpaid/COD failure cancels; paid failure becomes Delivery Failed. Both restore only recorded, unreturned sale deductions to their original warehouse inventory rows. Failure never changes financial records. Explicit COD collection at completion records the outstanding balance as a Sale payment; insufficient collection blocks completion, and excess tender is recorded as change. Payment, completion, returns and audit commit together, with one deterministic COD payment key per delivery. Restock markers prevent reapplying stock changes.

GET /deliveries/:id/settlement quotes an administrator/manager resolution. POST settle requires the reviewed quote and, when refunds are enabled, the existing payout validation fields. It records the authorized refund in RefundLedger; no external provider transfer is performed. When refunds are disabled it records manager settlement without a refund. Already-restored stock is skipped. Prepaid cancellations before final failure require financial review; the Delete action cancels eligible unpaid records while retaining their audit history.

Completion requires emptyCylinderReturned: true/false. Yes additionally requires warehouseId and returnedCylinders [{productId,qty}]. It reuses pickup/POS validation and the Cylinder-category SKU stock-in service, and journals return records atomically with completion. No performs no inventory adjustment. Cylinder returns do not change sales totals or payment records. POS delivery checkout now creates Preparing deliveries; COD does not create a paid payment record.
